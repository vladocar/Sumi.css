Tutorial

Build your first page with Sumi

In ten short steps you will build a one-page site for a calligraphy studio: navigation, a hero, course cards, a booking form, an FAQ and a dark mode. Most of it is plain HTML. Sumi does the styling.

  • ~20 min to finish
  • You need basic HTML
  • Works in any modern browser

1Add Sumi to a page

Sumi is a single CSS file with no JavaScript and no build step. Download sumi.min.css, put it next to your HTML file, and link it in the <head>.

Create a file called index.html with this starter:

Open the file in your browser. You should see a centered page with a bold heading, comfortable line spacing and the right colors for your system's light or dark mode.

Two lines matter. The viewport meta tag makes the layout work on phones. The lang attribute lets the browser hyphenate long-form text correctly, so set it to your page's language.

Use sumi.css instead of the minified file while you learn. It has comments that explain every section.

2Lay out the page

Sumi centers three elements automatically when they are direct children of <body>: <header>, <main> and <footer>. They get a maximum width of 72rem, side padding that adapts to the screen, and sensible vertical spacing. You don't add any classes.

Three classes cover the other layout cases:

ClassUse it when
.containerYou want the same centered width on another element, such as a <div> or a <section>.
.container-fluidYou want full width with side padding only.
.narrowYou want a reading column of 44rem, for a blog post or a sign-in form.

3Add navigation

A <nav> with two lists becomes a navigation bar: the first list sits on the left, the second on the right. Mark the current page with aria-current="page". Sumi highlights it, and screen readers announce it.

4Write the content

Headings, paragraphs, lists, quotes and code are styled from the element alone. Headings follow a fluid scale, so an <h1> is about 33px on a phone and 45px on a wide screen with no media queries on your side.

Three patterns make a hero section look finished:

  • <hgroup> groups a heading with an eyebrow (<h6>) above it and a subtitle (<p>) below it.
  • .lead makes an intro paragraph larger.
  • .display makes a headline larger still, for a landing page.

Long-form text

For an article or a blog post, wrap the text in .prose. It limits lines to about 68 characters, increases the line spacing slightly and turns on hyphenation. Add .serif to switch to a serif typeface, which many readers find calmer for long texts.

Why we grind our own ink

Bottled ink is convenient, but grinding a stick against the stone is part of the lesson. It takes about five minutes, and it slows you down before the first stroke.

One stroke, one breath. You cannot go back over a line.

Workshop rule no. 1

An <article> normally becomes a card (step 6). With .prose it stays plain text, because a long article should not sit in a box.

5Arrange content in a grid

.grid places its children in as many columns as fit, each at least 14rem wide. On a phone they stack into one column. You don't set any breakpoints.

Brushes, inksticks, stones and paper are ready on your desk.

Every student leaves with a finished, signed piece.

When you need exact columns, add .cols-2, .cols-3, .cols-4, .cols-6 or .cols-12. These apply from 48rem (768px) upwards; below that the grid is a single column. In a 12-column grid, children can take .span-2 to .span-9, or .span-full for a whole row.

For a single row of items, use .row (a wrapping flex row with a gap). Add .spread to push items to both ends. .stack is the vertical version.

6Show options in cards

Every <article> is a card. If the article starts with a <header> or ends with a <footer>, those become shaded bands across its full width. Put cards in a grid and they line up.

7Build a booking form

Form fields need no classes. Wrap each field in its <label> and it gets full width, padding and a focus ring. A <small> placed right after a field becomes helper text.

Experience

Try submitting the empty form. Fields turn red because a small script sets aria-invalid="true" on them. Sumi styles that attribute, and screen readers announce it too. Valid fields get aria-invalid="false" and turn green.

Two more patterns are worth knowing:

  • <input type="checkbox" data-style="switch"> draws a toggle switch instead of a checkbox.
  • <div data-style="group"> joins an input and a button into one control, like a search bar.

  • data-tooltip="…" shows a tooltip on hover and keyboard focus. Add data-placement="bottom" to show it below.
  • aria-busy="true" adds a spinner to any element. Remove the attribute when loading finishes.
  • .callout is a message box. Add .success, .warning or .danger for the color.

Fonts

Sumi uses each system's own interface font by default, so pages load with no font downloads. To use a web font, load it as usual and point a token at it. --s-font-body sets the text, and --s-font-heading sets the headings (it follows the body font unless you set it).

10Add your own CSS

Most of Sumi's element styles sit inside :where(), which gives them zero specificity. Any selector you write wins, without !important and without long selector chains.

Build new components from Sumi's tokens, as the badge above does. They then follow dark mode and your brand colors automatically. The tokens you'll use most are --s-text, --s-muted, --s-bg, --s-surface, --s-border, --s-primary and --s-radius.

Browser support

Sumi works in current versions of Chrome, Edge, Firefox and Safari. It relies on :where(), :has() and color-mix(), which are available from Chrome and Edge 111, Firefox 121 and Safari 16.2. Older browsers still show readable pages, with plainer hover and focus colors.
